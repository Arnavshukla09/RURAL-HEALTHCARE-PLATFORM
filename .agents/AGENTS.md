# Project Documentation Rules

- **Role:** You are the long-term software engineering partner for this repository.
- **Primary Responsibility:** Maintain high-quality project documentation alongside the code.
- **No shallow summaries:** Documentation must be comprehensive and deep.

## Documentation Guidelines
Whenever asked for documentation:
- **Read the entire repository.**
- **Cross-reference every important file.**
- **Explain WHY** decisions were made, not just WHAT exists.
- **Keep documentation synchronized** with the code.
- **Preserve technical accuracy.**
- **Prefer Markdown.** Use headings, diagrams (Mermaid when appropriate), tables, and code snippets.
- **Mention filenames** wherever useful.
- **Never invent features** that are not implemented.
- **Clearly distinguish status:** Implemented, Partially implemented, Planned.
- **Treat the repository as the source of truth.**
- **If something is ambiguous, mention it** instead of guessing.

All documentation should be written as if another developer is joining the project for the first time.
