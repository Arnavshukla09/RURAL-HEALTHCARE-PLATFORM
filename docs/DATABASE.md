# Database Reference: Rural Healthcare Platform

This document describes the schema, structure, relationships, indexes, and Row Level Security (RLS) policies powering the Rural Healthcare Platform via **Supabase (PostgreSQL 15+ with PostGIS extensions)**.

## 2. Table Definitions & Constraints

### 2.1 `patients`
Core patient and profile ledger.
- `id` (UUID, Primary Key, `default gen_random_uuid()`)
- `user_id` (UUID, Foreign Key `auth.users(id) ON DELETE CASCADE`, `UNIQUE`)
- `role` (TEXT, `CHECK (role IN ('patient', 'doctor', 'admin'))`, `DEFAULT 'patient'`)
- `first_name`, `last_name`, `email`, `phone`, `emergency_contact` (TEXT)
- `preferences` (JSONB, default `'{}'::jsonb`)
- `created_at`, `updated_at` (TIMESTAMPTZ)

**Security Hardening (Migration `09_scale_and_security.sql`):**
Users are strictly prevented from escalating their own privileges. The RLS update policy allows users to update only profile information, and an SQL trigger `prevent_patient_role_escalation` cancels any attempt by non-admins to change `role` or `user_id`.

### 2.2 `appointments`
Teleconsultation and clinic booking registry.
- `id` (UUID, Primary Key, `default gen_random_uuid()`)
- `patient_id` (UUID, References `patients(id) ON DELETE CASCADE`)
- `provider_id` (UUID, References `healthcare_providers(id) ON DELETE RESTRICT`)
- `appointment_date` (TIMESTAMPTZ, NOT NULL)
- `duration_minutes` (INTEGER, DEFAULT 30)
- `status` (TEXT, `CHECK (status IN ('scheduled', 'in_progress', 'completed', 'cancelled'))`, DEFAULT `'scheduled'`)
- `notes` (TEXT)
- `consultation_type` (TEXT, `CHECK (consultation_type IN ('teleconsult', 'in_person', 'camp'))`, DEFAULT `'teleconsult'`)
- `teleconsult_room_id` (TEXT, NOT NULL, Cryptographic UUID for Jitsi rooms)

**Double-Booking Prevention Constraint:**
A unique partial index guarantees that two scheduled appointments cannot exist for the same provider at the exact same time slot:
```sql
CREATE UNIQUE INDEX idx_appointments_provider_slot_active
ON appointments (provider_id, appointment_date)
WHERE status = 'scheduled';
```
When violated, Postgres throws error code `23505`, which API route `/api/appointments` maps directly to HTTP `409 Conflict` (`code: "SLOT_TAKEN"`).

### 2.3 `medical_records`
Patient electronic health records, prescriptions, and diagnostic reports.
- `id` (UUID, Primary Key, `default gen_random_uuid()`)
- `patient_id` (UUID, References `patients(id) ON DELETE CASCADE`, NOT NULL)
- `provider_id` (UUID, References `healthcare_providers(id) ON DELETE SET NULL`)
- `appointment_id` (UUID, References `appointments(id) ON DELETE SET NULL`)
- `record_type` (TEXT, `CHECK (record_type IN ('diagnosis', 'prescription', 'lab_result', 'vaccination', 'other'))`, NOT NULL)
- `content` (TEXT, NOT NULL)
- `file_url` (TEXT)
- `metadata` (JSONB, DEFAULT `'{}'::jsonb`)
- `record_date` (TIMESTAMPTZ, DEFAULT NOW())
- `created_at` (TIMESTAMPTZ, DEFAULT NOW())
- `updated_at` (TIMESTAMPTZ, DEFAULT NOW())

### 2.4 `health_data`
Temporal biometric indicators and vitals log.
- `id` (UUID, Primary Key, `default gen_random_uuid()`)
- `patient_id` (UUID, References `patients(id) ON DELETE CASCADE`, NOT NULL)
- `metric_type` (TEXT, NOT NULL) — e.g. `'heart_rate'`, `'blood_pressure'`, `'blood_sugar'`, `'temperature'`, `'oxygen_level'`
- `metric_value` (TEXT, NOT NULL)
- `unit` (TEXT)
- `device_id` (TEXT)
- `recorded_at` (TIMESTAMPTZ, DEFAULT NOW())
- `created_at` (TIMESTAMPTZ, DEFAULT NOW())

### 2.5 `processed_client_ops`
Idempotency table for offline sync queue replay.
- `client_op_id` (UUID, Primary Key)
- `user_id` (UUID, References `auth.users(id) ON DELETE CASCADE`, NOT NULL)
- `op_type` (TEXT, NOT NULL)
- `processed_at` (TIMESTAMPTZ, DEFAULT NOW())

When the client flushes its IndexedDB offline outbox, each operation sends its client-generated UUID. If the server already contains that `client_op_id`, the operation is skipped without error, guaranteeing atomic at-most-once execution across network retries.

### 2.6 `healthcare_facilities`
National geospatial directory of healthcare facilities, hospitals, clinics, and individual registered doctors across India.
- `id` (UUID, Primary Key, `default gen_random_uuid()`)
- `osm_id` (BIGINT, UNIQUE) — Natural deduplication key from OpenStreetMap nodes/ways/relations.
- `name` (TEXT, NOT NULL) — Facility or practitioner name.
- `type` (TEXT, NOT NULL) — One of `'hospital'`, `'clinic'`, `'doctors'`, `'pharmacy'`, `'lab'`, `'health_post'`.
- `address` (TEXT) — Human-readable road, street, or locality address.
- `phone` (TEXT) — Public contact or emergency phone number.
- `district` (TEXT) — Local Government Directory (LGD) district name.
- `state` (TEXT) — LGD state name.
- `lat` / `lon` (DOUBLE PRECISION, NOT NULL) — WGS84 decimal coordinates.
- `geom` (GEOGRAPHY(Point, 4326)) — Automatically calculated PostGIS geography point generated via trigger `trg_set_facility_geom`.
- `tags` (JSONB, DEFAULT '{}') — Unstructured metadata attributes including `speciality`, `emergency`, `opening_hours`, and `operator`.

**Current Scale Metrics:**
- Total facilities indexed: **136,743**
- Registered doctors & private practitioners (`type='doctors'`): **9,083**
- Coverage: All **36 States & Union Territories** (28 States + 8 UTs, including Ladakh, Andaman & Nicobar, and merged DNH & DD) and **725 Districts** of India.
- Attribution: **Data © OpenStreetMap contributors (ODbL 1.0)**.
- Storage footprint: **<50 MB** (<10% of Supabase 500 MB free tier, verified via `pg_database_size()`).

## 4. Row Level Security (RLS) Policy Matrix

| Table | Patient Access | Doctor Access | Admin Access | Demo Admin Mode |
|---|---|---|---|---|
| `patients` | Own row (`SELECT`, `UPDATE` non-role) | Care relationship patients only (`SELECT` via `has_care_relationship`) | Directory oversight (`SELECT`, `DELETE`) | `SELECT` only; role edits & deletes prohibited |
| `healthcare_providers` | Public verified (`SELECT`) | Own profile (`SELECT`, `UPDATE`) | All rows (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) | Read only |
| `appointments` | Own appointments (`SELECT`, `INSERT`, cancel) | Assigned appointments (`SELECT`, complete) | Directory oversight (`SELECT`, `DELETE`) | `SELECT` only; mutations blocked |
| `medical_records` | Own records (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) | Assigned patients under care (`SELECT`, `INSERT`) | Confidentiality: `SELECT` denied directly (redacted via API); `DELETE` for moderation | Read denied; mutations blocked |
| `access_audit_log` | Own rows (`SELECT`, `INSERT`) | Own rows (`SELECT`, `INSERT`) | Audit review (`SELECT`); updates/deletes revoked | Read only |
| `health_data` | Own vitals (`SELECT`, `INSERT`, `UPDATE`) | Care relationship patients (`SELECT` via `has_care_relationship`) | Aggregate metadata | Read only |
| `processed_client_ops` | Own ops (`SELECT`, `INSERT`) | Own ops (`SELECT`, `INSERT`) | All ops (all ops) | Read only |
| `notifications` | Own notifications (`SELECT`, `UPDATE is_read`) | Own notifications (`SELECT`, `UPDATE is_read`) | All notifications (`SELECT`, `INSERT`) | Read only |
| `healthcare_facilities`| Public (`SELECT`) | Public (`SELECT`) | All facilities (all ops) | Read only |
| `chat_cache` | None | Moderation (`SELECT`, `UPDATE`) if verified doctor | Full moderation (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) | Read only |

## 5. Doctor-Patient Confidentiality & Care-Relationship Functions

### `has_care_relationship` Security Definer Function
Restricts clinician visibility exclusively to patients with whom an active or scheduled appointment exists:
```sql
CREATE OR REPLACE FUNCTION public.has_care_relationship(p_patient_id uuid)
RETURNS boolean
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, auth
STABLE
AS $$
BEGIN
  -- Returns true if current auth.uid() doctor has an appointment or referral with p_patient_id
  RETURN EXISTS (
    SELECT 1 FROM public.appointments a
    WHERE a.patient_id = p_patient_id
      AND (a.provider_id = auth.uid() OR a.provider_id IN (
        SELECT hp.id FROM public.healthcare_providers hp WHERE hp.user_id = auth.uid()
      ))
  );
END;
$$;
```

### `guard_demo_admin_safety` Trigger
Prevents preview demo accounts (`admin@ruralhealth.demo`) from mutating live records or dropping data:
```sql
CREATE OR REPLACE FUNCTION public.guard_demo_admin_safety()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, auth
AS $$
DECLARE
  v_user_email text;
BEGIN
  SELECT email INTO v_user_email FROM auth.users WHERE id = auth.uid();
  IF v_user_email ILIKE '%demo%' OR v_user_email = 'admin@ruralhealth.demo' THEN
    RAISE EXCEPTION 'Demo admin mode restricted: Modifying or destructive operations are prohibited for preview accounts.';
  END IF;
  RETURN COALESCE(NEW, OLD);
END;
$$;
```

## 5. PostGIS Spatial RPC Functions

### `nearby_facilities` Function
Calculates spherical distance using PostGIS geography types:
```sql
CREATE OR REPLACE FUNCTION nearby_facilities(
    p_lat double precision,
    p_lon double precision,
    p_radius_km double precision DEFAULT 50,
    p_type text DEFAULT 'all',
    p_limit integer DEFAULT 50
)
RETURNS TABLE (
    id uuid,
    name text,
    type text,
    address text,
    phone text,
    lat double precision,
    lon double precision,
    distance_km double precision
)
LANGUAGE sql STABLE
AS $$
    SELECT
        f.id,
        f.name,
        f.type,
        f.address,
        f.phone,
        f.lat,
        f.lon,
        round((ST_Distance(f.geom, ST_SetSRID(ST_MakePoint(p_lon, p_lat), 4326)::geography) / 1000)::numeric, 1)::double precision AS distance_km
    FROM healthcare_facilities f
    WHERE
        ST_DWithin(f.geom, ST_SetSRID(ST_MakePoint(p_lon, p_lat), 4326)::geography, p_radius_km * 1000)
        AND (p_type = 'all' OR f.type = p_type)
    ORDER BY f.geom <-> ST_SetSRID(ST_MakePoint(p_lon, p_lat), 4326)::geography
    LIMIT LEAST(p_limit, 100);
$$;
```
