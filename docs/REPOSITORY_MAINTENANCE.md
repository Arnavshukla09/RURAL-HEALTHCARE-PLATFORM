# Repository Maintenance

Updated 24 November 2026 against local baseline `97036cd`. This pass changes contributor documentation and validation tooling, not application behavior or database schema.

## Preserved Boundaries

The existing feature structure already passes the module-size and unused-file gates. No application component, compatibility export, route, test journey, dataset, public language pack, model adapter or migration was removed. Reorganizing working feature paths would churn imports, voice registrations and audit references without a demonstrated benefit.

| Keep | Reason |
|---|---|
| `components/<feature>/index.tsx`, `parts/`, hooks and types | Existing UI ownership boundaries |
| Small top-level compatibility exports | Preserve consumers and Windows-safe explicit import resolution |
| `lib/services/` and lean `app/api/` handlers | Separate business authorization from transport |
| `public/data/assistant/`, PWA icons, avatar and facility packs | Runtime/offline assets, even when generated by maintained scripts |
| `supabase/migrations/` and SHA-256 manifest | Immutable database history; forward changes only |
| `docs/history/`, dated audits and metadata reports | Technical history, incident disclosure and scoped evidence |
| Ignored credentials, raw CSVs, `scratch/`, installed dependencies and models | Local/operator inputs; not assumed disposable |

## Changes in This Pass

- Preserved all engineering/security invariants in root `CONTRIBUTING.md`, replacing the tracked repository-only agent instruction file. Local editor/coding-tool folders are ignored.
- Split the large component checker into an orchestration entry point and an importable source-analysis module. TypeScript's parser now checks multiline imports, re-exports and literal dynamic imports rather than matching import-looking text with a line regex.
- Retained all quality categories: imports/exports, types, lint, unit tests, sealed migrations, unused files/dependencies and size limits. The API ceiling is now enforced literally as fewer than 150 lines. Only exact data catalogs and `components/ui/` are exempt.
- Removed hardcoded fallback test counts and claims that a nonexistent tracked pre-commit hook aborts every commit. CLI and CI invocations remain authoritative.
- Added direct npm commands for source, types, documentation, publication, client boundaries and browser tests; `npm run check:components` remains backward-compatible.
- Restored a code-linked study guide covering the previous learning topics without obsolete broad-doctor RLS examples, stale paths, AI-authorship labels or unsupported certification/cost claims.
- Extended local-link validation to `CONTRIBUTING.md`. README sections, diagrams, attribution, historical evidence and application AI/speech features remain intact.

## Safe Local Cleanup

Disposable test caches/results, TypeScript incremental output and generated benchmark/Lighthouse reports may be deleted and regenerated. Do not delete every ignored file: ignored files can be important inputs, credentials or model installations. `.next/` and generated service-worker output are left available after build verification, remain ignored and can be recreated by a later build.

Before recursive deletion on Windows, resolve every exact target, confirm it is inside the repository and reject reparse points/junctions. Do not use broad wildcard cleanup or cross-shell path interpolation. Current machine-specific cleanup results and verification are recorded in [the changelog](CHANGELOG.md), not substituted into historical reports.

## Presentation and Attribution

Use ordinary contributor guidelines and factual technical prose. Keep local tool prompts/caches out of the published tree. Do not erase legitimate AI product functionality, model licenses, author copyright, incident records or Git commit history to make a provenance claim. Historical documents describe historical states and should not be treated as the current specification.

## Verification

Run `npm run check:components`, `npm run check:docs`, `npm run check:boundaries`, `npm run check:publication` and `npm run build`. Additional checker tests cover parsed import forms, export forms and narrowly scoped limits. The [study guide](STUDY_GUIDE.md) maps these tools to the concepts they exercise.

This cleanup does not certify production configuration, live database policies, device speech or clinical outcomes. Existing seeded database/browser CI evidence stays dated; new local checks must be reported separately.
